# Bauhaus redesign: review and release

## Implemented

- Branch `bauhaus`, based on `main`; six stages: shared system and copy, home, About, cases, responsive/accessibility, metadata/review.
- Shared Archivo typography, geometry, five-colour palette, neutral reading surfaces and desktop/mobile navigation.
- Three selected projects plus the secondary landing case. Stable IDs separate presentation from CV order.
- Spanish and English routes, locale switching, canonical URLs, redirects and CV downloads preserved.
- Physical press interaction: hover only with a hover-capable pointer, active on all inputs, no displacement with reduced motion.
- Social images and favicon use the same identity. The Open Graph image query is versioned to avoid reusing the old image cache.
- Previous local skill-installation changes are excluded from redesign commits.

## Automated verification

Run `npm run verify`, then serve the build and run `npm run verify:browser` as documented in the README. The browser suite writes a JSON report, mobile/desktop screenshots and an uncoloured-background print PDF to `/tmp/bauhaus-browser-qa`. GitHub Actions stores the same artifacts on each pull request.

The enlarged text scenario doubles computed text sizes. The 200% page-zoom scenario uses the equivalent half-width layout viewport. Real browser zoom and device inspection remain part of human review.

Font fallback metrics were measured from the installed Archivo Latin WOFF2 and the Arial-compatible Liberation Sans available on Linux. Archivo: units/em 1000, ascent 878, descent 210, x-height 526. Fallback: units/em 2048, x-height 1082. The x-height adjustment is 99.563%, ascent override 88.186%, descent override 21.092%, line gap 0%. Arial is preferred when installed; platform rendering may vary. The suite tests long hero words with loaded and fallback fonts and observes layout shift during a delayed cold font load.

Web Interface Guidelines review applies accessibility, focus, image sizing, font loading, navigation and touch rules. The approved visual brief takes precedence over generic style suggestions for uppercase headings, first-person copy and hard-shadow animation.

## Local verification result

- `npm run verify`: passed, twelve routes and local links.
- `npm run verify:browser`: passed, 87 layout/font scenarios, axe checks on all twelve routes, keyboard, touch, reduced motion and print.
- Delayed cold-font layout shift on the local mobile run: 0.07318. This is a local observation, not a production Core Web Vitals measurement.
- Mobile header: 108 px at 360 px; both long hero words remain intact with Archivo and fallback.
- Spanish/English social PNGs: 1200 × 630, visually inspected.
- Browser artifacts are local and also generated by pull-request CI; human review remains pending.

## Human review before merge

- [ ] Review home, About and all four cases in ES and EN on the pull-request deployment preview.
- [ ] Inspect intermediate tablet widths, real 200% browser zoom, keyboard focus and printed output.
- [ ] Confirm screenshots, dates, project descriptions and status remain accurate.
- [ ] Validate ES and EN URLs in LinkedIn Post Inspector. Inspect a WhatsApp link-preview draft without sending it. Use the deployed preview when publicly accessible. If a preview is protected, a platform rejects it or a personal session is required, record the limitation and leave the check pending for the owner before merge. No claim of platform validation is made until recorded below.
- [ ] Conduct the 30-second test with three people from technology or recruiting, unrelated to the project; exclude family members.

Ask each participant, without a prior explanation:

1. What does Ramiro do?
2. Which project would you open to assess his work, and why?
3. Where would you download his CV or contact him?

At least two of three must identify web development as the main activity, choose a project for a concrete reason and find CV or contact without help. Record difficulties, correct them and repeat if the threshold is not met. AI reviews do not count as participants.

## Release gate

- [ ] Build, static checks, browser checks and GitHub checks are green for the final commit.
- [ ] Human visual review and comprehension test passed.
- [ ] Social-preview checks completed or their external limitation explicitly recorded and accepted by the owner.
- [ ] Owner approves merging the pull request into `main`.

Do not merge automatically. No analytics is introduced. Incoming job proposals are a later outcome, not a promised result of the design.
